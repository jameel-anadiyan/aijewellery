Jewellery Variation Studio — Antigravity Build Plan
Oct 23, 2026 · @MOHAMED JAMEEL ANADIYAN
Build a React web app where you upload one jewellery photo, type the diamond count, and get back 10 new design sketches, each on its own card with a name, description and specs, ready to download. Antigravity builds it from this plan in 7 milestones, and your OpenAI key stays on a small Node server.
How the app works
Upload: drop a product photo (JPG, PNG or WebP, up to 10 MB) and enter the diamond count. Optional: SKU, stone size, metal and notes on what must stay the same.
Analyse: the server sends the photo and count to an OpenAI text model. It studies the design and returns 10 variation concepts as JSON: name, description, stone layout, setting, size estimate and an image prompt.
Generate: the server makes 10 separate GPT Image 2.5 requests, each with your photo as the reference and one concept's prompt. It runs 3 at a time, and each card fills in as its image arrives.
Review: each card shows the sketch, name, description, stone count and specs. Regenerate any card, or star the best ones.
Download: save a single PNG, or download the starred or all cards as a ZIP with a CSV of names and descriptions.
Every prompt repeats the exact diamond count you entered. Image models can still add or drop a stone, so check each card before downloading (see Known limits).

Rules the server enforces:
Exactly 10 variations, each with a unique name; if not, retry the analysis once.
Every stoneCount equals the count the user entered (per piece). If the model returns another number, the server overwrites it and rebuilds that prompt.
Errors come back as { error: { code, message } }: 400 bad input, 413 file too large, 422 blocked by moderation (moderation_blocked: change the request, never auto-retry), 429 rate limited (the client waits and retries), 500 anything else.
OpenAI setup
The app makes two kinds of OpenAI call: one text-model call that plans the 10 designs, then one GPT Image 2.5 call per design that draws it from your photo. OpenAI's current image models are gpt-image-2.5-sunburst, which it recommends where editing precision matters, and gpt-image-2.5-flare, which is faster.
server/.env (Antigravity writes .env.example; you paste the real key):
OPENAI_API_KEY=sk-...OPENAI_TEXT_MODEL=gpt-6-lunaOPENAI_IMAGE_MODEL=gpt-image-2.5-sunburstIMAGE_QUALITY=mediumIMAGE_SIZE=1024x1024IMAGE_FORMAT=pngMAX_PARALLEL=3PORT=8787
gpt-6-luna is a low-cost model that reads images and supports Structured Outputs; switch to gpt-6-astra if you want richer design ideas at a higher price. Confirm both IDs on OpenAI's models page before the first run, because names change with new releases.

Reliability
Run at most 3 image calls at once (p-limit). OpenAI says complex prompts can take up to 2 minutes, so set a 180-second timeout.
Retry rate-limit (429) and server (5xx) errors twice, after 2 s then 6 s. Never auto-retry quota or moderation errors.
Log only the job id, variation index, timing and error code; never the key or the image data.
Prompts the app sends
Keep both prompts in server/src/prompts.ts so you can tune them without touching the rest of the code. The server fills the {placeholders}.
Analysis prompt (system message for the text model):
You are a senior fine-jewellery designer. You receive one product photo and its exact diamond count per piece: {count}.1. Study the original: product type, metal colours, head or motif, how the stones are arranged, setting style, and band or earring-back type.2. Design 10 new variations for a lightweight collection. Rules for every variation:   - EXACTLY {count} diamonds per piece, all the same size as the original. No extra accent stones. No coloured stones unless the original has them.   - Lightweight: thin wire (about 1.0-1.2 mm), open and airy shapes, no heavy solid metal.   - Same design family: same mood and proportions, two-tone if the original is two-tone, same band or earring-back type.   - Clearly different from each other. Spread them across a new motif shape (heart, round, marquise, pear, square), a new stone arrangement (cluster, two rows, split groups) and a new construction (spiral, bypass, infinity, crossover).   - Original designs only: no brand look-alikes, no logos or text.3. For each variation return: name (2-3 words), description (max 2 sentences), stoneCount, stoneLayout (where each stone sits), setting, sizeMm (estimate), goldVsOriginal (lighter, about the same or more), and imagePrompt (a vivid visual description of the design for an image model).Return only JSON that matches the schema.

Draw ONE new jewellery design.Design: {name} - {description}Details: {imagePrompt}Stones: EXACTLY {count} round brilliant diamonds, laid out as: {stoneLayout}. Costs, speed and limits
A 10-design run at medium quality should cost roughly $0.55–$0.65. That covers about $0.53 of images, roughly 1 cent per image for reading your reference photo, and well under 1 cent for the analysis. These are estimates. GPT Image 2.5 bills $8 per 1M image-input tokens and $30 per 1M image-output tokens, the same rates as GPT Image 2, so the figures below use GPT Image 2's per-image estimates. Speed: OpenAI says one image can take up to 2 minutes. With 3 running at once, expect a full set in roughly 2–8 minutes. Low quality and JPEG output are quicker, and gpt-image-2.5-flare has up to 50% lower latency than Sunburst.
Access: OpenAI may ask you to verify your organisation before GPT Image models work.
Rate limits depend on your OpenAI usage tier. Raise MAX_PARALLEL only if you never see 429 errors.
Cost controls in this plan: medium quality by default, the estimated cost shown before Generate, single-card regenerate instead of whole runs, and a cap of 20 runs per day once deployed.
Known limits and next ideas
The biggest limit is stone accuracy. Image models can add or drop a small diamond even when the prompt gives the exact number, so count the stones on each card before downloading and use Regenerate when one is off.
Sizes and gold use on the cards are the model's estimates from your photo, not measurements. Confirm them in CAD before costing.
The sketches are concept art, not production drawings, so very fine prongs may be simplified.
Moderation occasionally blocks a request. The card shows the reason, and you can edit the notes and retry.
Ideas to add once the basics work:
Stone check: after each image, ask the text model to count the visible diamonds and flag cards that don't match. Treat it as a hint, since it can miscount too.
Detail sheet: a "More detail" button that draws a top view, side view and numbered stone map for one chosen design.
Shopify drafts: turn starred designs into draft products in your SWA Diamonds store, with the name and description filled in.
History: a page of past runs you can search by SKU.
